# 2026-09-01 — LXC 105 "plane": Plane self-hosted (gestión de proyectos)

Nace de la decisión de integrar una herramienta de gestión de proyectos que conviva con
[[project-pm-agent]] (docs ligeras) y con ISO/IEC 29110 (infra crítica, según corresponda) — y que
además pueda retroalimentar el RAG del portafolio con lo que se documente ahí. Entre Plane y
OpenProject se eligió Plane: stack más liviano (React + Django + Postgres/Redis/RabbitMQ/MinIO,
sin Elasticsearch obligatorio como OpenProject), y trae *Pages* (wiki) además de *issues* en la
misma API con webhooks nativos — más apto para un solo usuario con agentes automatizando cosas
que la gestión formal (Gantt, time-tracking) que ofrece OpenProject para equipos grandes.

## LXC (OpenTofu, `environments/plane/`)

VMID 105, `192.168.8.93/24`, 4 cores, 6GB RAM, 30GB disco, `nesting=true` (mismo motivo que
`observability`: stack via docker-compose). Mismo token `tofu@pve` reusado de los otros
environments, pool `iac`.

## Despliegue de Plane

Instalado con el metodo oficial de self-host (`deployments/cli/community/` del repo de Plane,
descargado via el `setup.sh` publicado en cada release de GitHub) en vez de compilar desde
fuente — usa imagenes pre-construidas de `makeplane/*`, mucho mas rapido. `APP_DOMAIN` en
`plane.env` seteado a la IP del LXC (`192.168.8.93`) antes de arrancar, para que `WEB_URL` y
`CORS_ALLOWED_ORIGINS` resuelvan bien sin DNS propio todavia.

`./setup.sh install` (descarga `docker-compose.yaml` + `plane.env`, trae las imagenes) seguido de
`./setup.sh start` -- ambos con parametro posicional, no interactivo. 12 contenedores arriba
(web, admin, space, live, api, worker, beat-worker, proxy, postgres, redis, rabbitmq, minio),
migraciones de base de datos corridas automaticamente por el script. Verificado con `curl` real
(`HTTP 200` en `http://192.168.8.93/`) y `docker ps` (los 5 servicios con healthcheck en estado
`healthy`).

**Footprint real medido** (`docker stats`, stack recien arrancado, sin uso todavia): ~1.3GB de RAM
en total sobre los 6GB asignados al LXC -- el mas pesado de los servicios del portafolio hasta
ahora en cantidad de contenedores (12), pero el consumo real de memoria queda comodo.

## Pendiente (a proposito, siguiente iteracion)

- **Cuenta de administrador:** la creacion de la cuenta inicial es un paso de producto (email +
  password reales) que le corresponde al usuario hacer desde el navegador -- no se automatizo ni
  se genero por este agente.
- **Vault:** las credenciales internas (Postgres, Redis, RabbitMQ, MinIO) las genero el propio
  `setup.sh` de Plane dentro de `plane.env`, en el LXC -- todavia no migradas a Vault como
  `secret/plane` (mismo patron que `observability`/`devops-multiagent`). No son secretos expuestos
  fuera de la red interna de Docker del LXC, pero conviene alinear con el resto del portafolio.
- **Webhook hacia el RAG:** conectar los webhooks nativos de Plane (issues/pages creados o
  editados) para disparar reindexado de `rag-mcp-server`, en vez de indexar por polling.
- **`pm-agent` integrado con Plane:** por ahora `pm-agent` sigue escribiendo `docs/lite/` a mano en
  cada repo; la idea de que alimente Plane en vez de (o ademas de) markdown suelto queda para
  cuando la cuenta y el API token esten configurados.
